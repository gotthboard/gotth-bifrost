# Bifrost v0.1 product profile

Status: profile only; not a release and not implementation authorization

Authority: `governance/releases/v0.1.toml`

The first profile deliberately limits breadth so the safety and recovery model
can be proven end to end.

Within that bounded capability set, v0.1 is intended to exercise all three
deployment roles defined by `governance/deployment-profiles.toml`: router-only,
switch, and converged router-switch. Switch mode includes Layer-2 switching and
an admitted Layer-3 switching subset for SVIs, routed switchports, and
inter-VLAN/local-fabric routing; WAN-edge routing and NAT remain off unless the
router/converged profile admits them. Router mode includes Layer-3 forwarding
and Layer-4-aware stateful policy/NAT without requiring a user switching
domain. Role selection controls admitted effects; it does not install a
different edition or management plane. Management-only addresses are never
transit interfaces.

Included:

- `bfw-core`, `bfw-cli`, `bfw-web`, `bfw-identity`, and `bfw-plugin-sdk`
- `bfw-platform-linux` as the first product platform backend
- `bfw-firewall`, `bfw-network`, `bfw-switching`, and `bfw-routing`
- `bfw-dns`, `bfw-dhcp`, and `bfw-wireguard`
- `bfw-monitoring`, `bfw-logging`, `bfw-backup`, and `bfw-updater`

The separately versioned `bfw-installer` is a required build/distribution
component for the signed Alpine live ISO. It is pinned in build composition but
is not installed as a runtime service in the appliance.

Everything else in the catalog is deferred. In particular, v0.1 does not ship
GoKA HA, distributed fabric, Kubernetes-managed HA, multi-WAN, IDS/IPS, dynamic routing, alternate VPNs, captive portal,
reverse proxy, ACME/DDNS automation, or FreeBSD/Windows
product images.

The switching baseline uses the admitted Linux software bridge/VLAN facilities
and includes VLAN access/trunk behavior, FDB observation, STP, and LACP. Native
switch ASIC offload is optional and remains disabled unless a hardware/platform
adapter independently proves semantic parity, observation, failure, and
rollback behavior.

The profile remains blocked by Phase 0, exact Linux OS/kernel/architecture/image
selection, component repository creation, immutable pins, artifact/SBOM/
provenance digests, rollback mates, test-lab evidence, and independent review.
Empty fields in the draft composition are blockers, not wildcards.
